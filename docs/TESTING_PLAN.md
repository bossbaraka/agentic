# خطة الاختبارات — MUREEH Agent

## 1. الأدوات والتشغيل

- إطار `node:test` المدمج (صفر اعتماديات اختبار) مع `tsx`، كل ملف اختبار في
  عملية مستقلة وقاعدة SQLite مؤقتة لكل ملف (`tests/helpers/env.ts`).
- الأوامر:
  - `npm test` — مجموعة الوحدة/التكامل الرسمية (29 اختبارًا).
  - `npm run typecheck` — فحص الأنواع الكامل (0 أخطاء).
  - `npm run test:flow` — سيناريو المحادثة القديم (واتساب/تيليجرام).
  - `npm run test:smoke` — دخان واجهة تيليجرام من البداية للنهاية ضد خادم حي.

## 2. المصفوفة المغطاة

### أ. محرك الحجوزات (`tests/booking.test.ts`)
- إنشاء حجز ينتهي CONFIRMED ويسجّل إشغال الفتحة.
- **منع الحجز المزدوج** على نفس (التاريخ، الوقت) — الثاني يرمي `ServiceError`.
- Idempotency: نفس المفتاح يعيد الصف نفسه بلا ازدواج.
- رفض تاريخ/وقت غير صالح قبل اللمس بالقاعدة.
- رفض خدمة/باقة غير موجودة.
- الملكية: عميل لا يلغي ولا يعدّل حجز غيره.
- دورة الحياة: التعديل يحرّر الفتحة القديمة ويلغي تذكيراتها، الإلغاء يحرّر
  الفتحة، ومنع الإلغاء المزدوج.
- قوائم العميل لا تُظهر حجوزات غيره.

### ب. سجل الأدوات (`tests/tools.test.ts`)
- رفض أداة غير مسجّلة (`drop_database`) دون استثناء يصل للحلقة.
- رفض وسائط فاسدة (تاريخ/وقت/طول زائد) قبل التنفيذ.
- إنشاء حجز عبر الأداة ثم إدراجه في `get_customer_bookings` ثم إلغاؤه.
- رفض إلغاء حجز مملوك لجلسة أخرى.
- `get_services` يقرأ الكتالوج المزروع (لا hardcode).
- رفض تذكرة دعم بلا نص مشكلة.

### جـ. موجّه تيليجرام (`tests/router.test.ts`)
- `/start` يرسل اللوحة الدائمة والشاشة الرئيسية.
- الأوامر النصية للقوائم تُعترض؛ النص الحر يمر للوكيل الذكي.
- مسار أزرار كامل: فئة → خدمة → تاريخ → وقت → تأكيد، وينتج صف حجز صحيح.
- الحجز المزدوج من زبونين يرجع **تنبيهًا منبثقًا** بلا استثناء، بلا حجز ثانٍ.
- حماية الملكية على شاشة تفاصيل الحجز.
- تبديل اللغة يحدّث لغة المستخدم ولوحة المفاتيح.
- الأزرار غير التابعة للقوائم تُعلَّم `unhandled` ليمرّرها الموزّع للذكاء
  (توافق مع أزرار الردود السريعة القديمة).

### د. RBAC (`tests/rbac.test.ts`)
- غير الموظف لا يُحَل إلى دور.
- مصفوفة الصلاحيات لكل دور (STAFF/MANAGER/ADMIN/SUPER_ADMIN).
- إضافة موظف مسموح لـ SUPER_ADMIN ومرفوضة لـ STAFF/MANAGER.
- تفعيل/إيقاف خدمة محصور بمن يملك `services.write`.
- تغيير حالات الحجز حسب الصلاحية.

### هـ. دخان التكامل الحي (`scripts/smoke-menu.ts`)
عبر `/internal/simulate` على خادم في وضع التجربة: مسار حجز كامل لعميلين،
منع الازدواج، شاشات (قوائم/تفاصيل/دعم/عن)، طلب خدمة رقمية، إلغاء، محاولة
تطفّل على حجز غريب، ورؤية تنبيه طابور الإشعارات للفريق في السجلات.

## 3. ما فُحص يدويًا

- إقلاع نظيف: ترحيل v1، بذر 9 خدمات/فئتين، عامل الإشعارات، أوامر البوت.
- `/health` يعرض حالة القاعدة وعمق الطابور؛ `/api/sessions` يعرض بطاقات DB.
- الاستيراد القديم آمن عند إعادة التشغيل (مفاتيح ثبات).
- سلوك عرض التوكنات/التنبيهات في وضع DEMO (لا استدعاءات شبكة).

## 4. الحالات المقترحة لاحقًا (ليست مانعة للإطلاق)

- اختبار حمل/سباق حقيقي عبر عمليات متوازية (القيد الحالي مختبر منطقيًا بمحاكاة
  الطلب المتسابق؛ المعاملة `BEGIN IMMEDIATE` تضمن ذلك على مستوى التخزين).
- اختبارات قناة واتساب end-to-end مع خادم محاكٍ لـ Graph API.
- اختبارات عقود المخرجات للنموذج (JSON/Function calling) بمثبّتات ردود.
