## 2) التغييرات المنفذة (بترتيب الأولوية)

**خط الأنابيب (المرحلة 3)** — `agent.ts`: استخراج حقائق تلقائي → تحليل حتمي (نية/ألم/اعتراض) → تثبيت حالة العميل → جسر الجلسة → بناء برومبت معياري → LLM مع سلسلة احتياط → تنفيذ أدوات → **تحقق ما قبل الإرسال** → تسجيل مقاييس.

**النية (4):** `intelligence/intent.ts` — 25 نيّة + unclear، ترجيح بالأوزان، أجوبة قصيرة تُفسَّر بآخر سؤال بوت («25» بعد «كم طاولة؟»)، REAL_QUESTION يفكك تحية+سؤال.

**حالة العميل (5):** `intelligence/customerState.ts` + هجرة `customer_agent_state` — حقائق موثوقة بثقة، آلام ≤5، اعتراضات ≤4، نية شراء لاصقة، بذرة من ملفات قديمة (`bootstrapCustomerState`).

**رحلة بيع (6):** `intelligence/stages.ts` — DISCOVERY→QUALIFICATION→PROBLEM_IDENTIFICATION→SOLUTION_MAPPING→RECOMMENDATION→CONSIDERATION→OBJECTION_HANDLING→PURCHASE_INTENT→ONBOARDING→CUSTOMER_SUPPORT، `deepen` للأمام فقط، حالة الإطلاق المنفَّذة (`launchStatus`) لها الكلمة الأخيرة.

**ذكاء الألم (7):** `painPoints.ts` — قواعد ألم→حل→سؤال تأهيل؛ يُعرض الاستنتاج فقط للعميل، السلسلة الداخلية لا تُكشف.

**الاعتراضات (8):** `objections.ts` — 6 أنواع + سياسة لكل نوع (approach/avoid)؛ الفرع السعري: اعتراف→أرقام رسمية→قسط للطاولة→باقة أدنى إن لزم، بلا «هل تريد الاشتراك؟».

**الأدوات (9):** `tools.ts` — كل الأدوات بيانات منظمة + `userMessage` factual بلا CTA؛ تخويل حتمي في الكود (`runTool`)، لا قرارات من النموذج.

**مصدر السعر الوحيد (10):** `plans.ts` (300/550/850، سنوي 3000/5500/8500) → خدمة → أدوات → النموذج؛ حارس `price_violation` يصلح أي رقم مخالف قبل الإرسال (مثبت: 620→550)؛ knowledge/business-info.md أُزيلت منه كل أسعار الباقات.

**فصل الذكريات (11):** معرفة النشاط (knowledge/*.md) ≠ ذاكرة العميل الدائمة (users+customer_agent_state) ≠ سياق الجلسة (sessions+ملخص) ≠ حالة البيع (stage/score).

**الجلسة مقابل العلاقة (12):** الجلسة تُلخَّص وتُدوَّر؛ العميل العائد يستأنف من حالته المخزنة («أنا رجعت بدي أكمل» — مثبت E2E).

**سياسة الاستجابة (13):** `responsePolicy.ts` — الجواب أولًا، CTA فقط بعد ألم معروف أو نية شراء، حذف تكرار الدعوة، منع البيع في رسائل الدعم (غير مشروط)، إصلاح الأسعار، تنظيف تسربات (`reasoning_leak`/`qr:`/أسوار كود/JSON خام).

**العربية الطبيعية (14):** `prompts/conversationPolicy.ts` — لهجة حية بلا «ممتاز» متكرر ولا إطلاق إيموجي/قوائم؛ الأرقام فقط من الأدوات.

**النقاط الحتمية (16):** `leadScore.ts` — قاعدة 10 + علاقة متراكمة (مرحلة، نية 30، آلام 6×≤3، اعتراضات 6×≤2، عائد 8، بروفايل ≤35) + زخم الرسالة؛ فئات 0–30/31–60/61–80/81–100؛ النموذج لا يخترع نقاطًا.

**التحويل البشري (17):** `handoffService` — `HandoffMeta{stage,leadScore,plan,tables,restaurant,objection}` في تنبيه الفريق والتدقيق.

**موثوقية LLM (18/19):** سلسلة `gemini-2.5-flash → 2.5-flash-lite → flash-latest` (معرّفات مُتحققة من التوثيق الرسمي 2026-09-04؛ كل معرّفات 2.0/preview الميتة أُزيلت)، مهلة + تصنيف خطأ (quota/model_not_found/invalid_key/timeout)، `aiStatus` في كل رد وسجل و`/health`.

**برومبت معياري (20):** corePolicy/conversationPolicy/salesPolicy/safetyPolicy + TOOL + ذاكرة + ذكاء + آخر رد + knowledge.render() + عقد إخراج JSON.

**التحقق ما قبل الإرسال (21):** `applyResponsePolicy` قبل كل صادر — إصلاح/تنظيف/تسجيل، وتُسجَّل النتائج في `aiMetrics`.

**الأمان (26/27):** تخويل الأدوات حتمي بالكود، حقن التعليمات مقاوم (تعليمات صريحة + تعقيم مخرجات)، عزل مستأجرين على الخادم (كل استعلام بحقل المستأجر من الجلسة لا من النموذج)، RBAC للوح.

## 3) المعمارية النهائية (مختصر)

```
رسالة العميل
  → normalize + autoExtractFacts (ذاكرة دائمة)
  → analyzeMessages: intent(25) + pains + objections + purchase/human/support
  → applyAnalysis: applyAnalysis→state (مرحلة للأمام فقط، sticky intent/pains)
  → computeLeadScore: قاعدة+علاقة+زخم (حتمي)
  → buildSystemPrompt: role→session→CORE→CONVERSATION→SALES→SAFETY→TOOL
      →memory→summary→intelligence→lastAssistant→knowledge→OUTPUT_CONTRACT
  → generateReply: Gemini (سلسلة احتياط) → mock محلي عند الفشل — الحالة دائمًا معلنة
  → tools عند الحاجة: بيانات منظمة فقط
  → applyResponsePolicy: أسعار/CTA/تسرب/تكرار — إصلاح قبل الإرسال
  → إرسال + aiMetrics.recordReply + log.ai (model/latency/aiStatus)
```

## 5) المخاطر المتبقية

1. **جودة صياغة LLM الحية** غير قابلة للقياس دون مفاتيح/شبكة — مغطاة إنتاجيًا بـ aiMetrics (تدهور/توقف/كمون) لكن لا اختبار نصّي أوتوماتيكي للأسلوب.
2. **معرّفات Gemini** مُتحققة بتاريخ 2026-09-04؛ إيقاف نماذج مستقبلًا يُدار بالسلسلة الاحتياطية + `/health`.
3. **تذبذب زخم النقاط** عند القمة (88↔78 بين دور نية شراء ودور عادي) — داخل النطاق ومقصود، لكن يستحق مراقبة.
4. **رسائل ألم مجردة تُصنف unclear** (قرار مقبول: الحالة تحمل الألم والرد يتعامل معه) — قد تُحسَّن بنيّة `pain_report` مستقبلًا.
5. **جسر اللغة** للجلسة يكتشف اللغة بخوارزمية منفصلة عن طبقة الذكاء (توحيد مؤجل).
6. **توقيع ويب هوك واتساب/تليجرام يُتخطى إذا APP_HASH غير مضبوط** — سلوك سابق لم يُغيَّر (خارج النطاق)، موثّق كخطر نشر.
7. **الـeval يقيس الطبقات الحتمية**؛ أي إضافة نوايا/قواعد جديدة يجب أن يصاحبها سيناريو في `scripts/eval-conversations.ts` (العرف المعمول به).

## 6) كيف تُدار التعديلات مستقبلًا

- كل قاعدة نمط تُكتب **بسلامط `normalize()`** (ا لا أ — ه لا ة — ي لا ى) — مخالفة ذلك = فشل صامت.
- أي سعر/باقة جديد: `plans.ts` فقط — الأدوات والتقارير تتبعه تلقائيًا، وقاعدة المعرفة لا تحمل أرقامًا.
- `npm test && npm run eval` قبل كل دمج؛ كلاهما بلا شبكة وم deterministic.
