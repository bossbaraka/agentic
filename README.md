# 🟢 بوت واتساب الذكي — WhatsApp AI Agent

بوت واتساب تفاعلي يردّ على العملاء بالعربية عبر **WhatsApp Cloud API الرسمي**،
بدماغ **Google Gemini**، مع **لوحة تحكم حية** تتيح لك مراقبة كل محادثة والتدخل يدويًا في أي لحظة.

> ## 🍽️ مخصَّص حاليًا لمنصة **مُريح** للخدمات الإلكترونية
> تم "تدريب" البوت (هندسة معرفة) على بيانات منصة مُريح المستخرجة من مستودع
> `restaurantsMureeh`: باقات وأسعار حقيقية (₪)، المزايا، الأسئلة الشائعة، مسار التفعيل،
> والدعم التقني للمشتركين. مهمته: **الرد على استفسارات الاشتراك + قيادة العميل الجاهز
> نحو تفعيل اشتراكه** (تسجيل ليد + تنبيه فريق المبيعات) + دعم المشتركين (تذاكر).
> التفاصيل في قسم «تخصيص منصة مُريح» أدناه.

```
┌──────────┐   webhook    ┌──────────────────────────────┐    API     ┌─────────┐
│ واتساب   │ ───────────▶ │  خادم Fastify (هذا المشروع)  │ ────────▶ │ Gemini  │
│ العميل   │              │  ─ تحليل وتوحيد الرسائل      │           └─────────┘
└──────────┘              │  ─ جلسات وسياق وملخصات       │
     ▲                    │  ─ فهم صور/صوت/PDF           │    live    ┌─────────┐
     │   رد مقسّم         │  ─ أدوات (حجز/طلب/تذكرة)     │ ◀────────▶ │ لوحة    │
     └─────────────────── │  ─ تحويل لموظف بشري          │   WebSocket│ التحكم  │
                          └──────────────────────────────┘            └─────────┘
```

## ✨ المزايا

| الميزة | التفصيل |
|---|---|
| 🧠 **سياق حقيقي** | يحفظ المحادثة، ويلخّصها تلقائيًا عندما تطول، ويستأنف بعد فترة الخمول |
| ⏳ **تجميع الرسائل** | العميل يرسل ٣ رسائل متتابعة؟ البوت ينتظر ويردّ **مرة واحدة** بشكل متماسك |
| 🖼️ **فهم الوسائط** | صور، رسائل صوتية، فيديو، وملفات PDF — تُمرَّر لـ Gemini مباشرة |
| 🔧 **أدوات (Function Calling)** | تفاصيل باقة، توصية باقة، تسجيل تفعيل اشتراك (ليد)، فتح تذكرة دعم |
| 🙋 **تحويل لبشري** | تلقائي عند الغضب/الشكوى/نقص المعلومة، أو يدوي بأمر `/بشري` |
| 🖥️ **لوحة تحكم حية** | كل رسالة تظهر فوريًا، تردّ يدويًا، تغيّر حالة أي محادثة |
| 📚 **قاعدة معرفة** | علّم البوت عن نشاطك بملفات Markdown — بدون لمس أي كود |
| ⌨️ **مؤشر "يكتب…"** | يعلّم الرسالة مقروءة ويظهر مؤشر الكتابة قبل الرد |
| 🔒 **أمان** | تحقق HMAC من توقيع Meta، كبح معدل، حماية من حقن التعليمات |
| 🧪 **وضع تجربة كامل** | جرّب كل شيء بدون رقم واتساب وبدون مفاتيح |

## 🍽️ تخصيص منصة مُريح (ما الذي «تعلّمه» البوت)

قاعدة المعرفة (`knowledge/`) الآن تحتوي بيانات مُريح الفعلية، والأدوات مبنية
حول دورة الاشتراك. هذا هو «التدريب» — تعديل معرفي/نصّي قابل للتحديث في أي لحظة:

| ما تعلّمه البوت | أين يوجد |
|---|---|
| الهوية (منصة مُريح / MUREEH OS) وقنوات التواصل | `knowledge/business-info.md` |
| **الباقات الثلاث والأسعار بال₪** (300 / 550 / 850) + مزايا كل باقة + توفير الدفع السنوي | `src/agent/plans.ts` (المصدر الوحيد للأرقام) + `business-info.md` |
| **مسار التفعيل** (4 خطوات) وما يحدث بعد الاشتراك | `business-info.md` |
| **حالات الطلب** (استلام ← تحضير ← جاهز ← تقديم) وحالات الطاولة ونداء النادل | `business-info.md` |
| أسئلة تقنية شائعة من المشتركين (KDS، إضافة طبق، فاتورة، موظف جديد) | `business-info.md` |
| النبرة + أمثلة ردود جيدة/سيئة بأسلوب «مستشار مبيعات» | `knowledge/tone-and-replies.md` |
| **4 أدوات** مخصصة لدورة الاشتراك | `src/agent/tools.ts` |

### الأدوات الأربع (Function Calling)

| الأداة | متى يستدعيها | ما تفعله |
|---|---|---|
| `get_plan_details` | سؤال عن سعر/مزايا باقة محددة | ترجع الأسعار الرسمية من `plans.ts` (بدون أي تخمين) |
| `recommend_plan` | ذكر العميل عدد طاولاته أو احتياجاته | توصية حتمية: >50 طاولة/فروع → المؤسسات، ≥15 طاولة أو كDS/تحليلات → الاحترافية، وإلا الأساسية |
| `capture_subscription_lead` | العميل قرّر الاشتراك بوضوح + جمعت البيانات | تحفظ ليد في `data/leads.json` + **تنبيه فوري لفريق المبيعات** برقم مرجع `SUB-…` |
| `create_support_ticket` | مشترك لديه مشكلة تقنية | تحفظ تذكرة في `data/tickets.json` + تنبيه الفريق + تحويل للمحادثة البشرية |

### منطق التوصية (deterministic)
`src/agent/plans.ts → recommendPlan()`: نفس الأرقام التي يجب أن يستخدمها النموذج،
لكن محسوبة برمجيًا فلا يخطئ البوت في السعر أبدًا. عدّل هنا فقط عند تغيير أي سعر.

### تدفق التفعيل (Funnel)
```
تحيّة → «كم طاولة عندك؟» → توصية باقة + سعر → «تبيني أجهز لك التفعيل؟»
  → جمع: اسم / مطعم / مدينة / طاولات / باقة (سؤال واحد في كل مرة)
  → capture_subscription_lead → تأكيد + تنبيه الفريق (SUB-…) → الموظف يكمل التفعيل
```

> ⚠️ **طريقة دفع الاشتراك** غير محددة في قاعدة المعرفة — البوت لا يخمّن ويحوّل لموظف.
> إذا حدّدت طريقة الدفع (حوالة/بطاقة/تحويل)، أضِفها في `business-info.md` وقيد قاعدة «لا تخمّن».

## 🔑 تفعيل الذكاء الحقيقي (Gemini)

1. افتح **https://aistudio.google.com/apikey** وأنشئ مفتاحًا (مجاني).
2. في `.env`:
   ```env
   DEMO_MODE=false
   GEMINI_API_KEY=ضع_المفتاح_هنا
   GEMINI_MODEL=gemini-2.5-flash
   ```
3. أعد التشغيل: `npm run start`

| الموديل | متى تستخدمه |
|---|---|
| `gemini-2.5-flash-lite` | أرخص خيار، كافٍ للأسئلة المباشرة |
| `gemini-2.5-flash` | **الموصى به** — توازن سعر/جودة/سرعة |
| `gemini-3.5-flash` | أذكى، للحالات المعقّدة (أغلى) |

## ✈️ تيليجرام — القناة النشطة الآن

> **الحالة:** واتساب موقوف مؤقتًا بسبب مشكلة مع Meta (`WHATSAPP_ENABLED=false`).
> البوت يخدم **نفس الدماغ** (الجلسات، الأدوات، قاعدة المعرفة، اللوحة) عبر تيليجرام.
> الاستعادة: `WHATSAPP_ENABLED=true` + مفاتيح Meta → `npm run start`. لا تغيير كود.

### ١) إنشاء البوت (دقيقتان)

1. في تيليجرام راسل **[@BotFather](https://t.me/BotFather)**
2. أرسل `/newbot` — اختر اسمًا وusername ينتهي بـ `bot`
3. انسخ التوكن الصادر: `7123...:AA...`
4. (اختياري) لمعرفة `chat id` الخاص بك: راسل **@userinfobot**

### ٢) في `.env`

```env
TELEGRAM_BOT_TOKEN=7123...:AA...
TELEGRAM_HUMAN_CHAT_ID=              # معرف فريقك — يصله تنبيه التحويل البشري والليدات
DEMO_MODE=false
WHATSAPP_ENABLED=false               # واتساب موقوف — غيّره لـ true عند حل مشكلة Meta
```

### ٣) التشغيل — **لا حاجة لنفق أو HTTPS**

```bash
npm run start
```

عند غياب `TELEGRAM_WEBHOOK_URL` يعمل البوت بـ **Polling** (استعلام دوري من
Bot API) — يعمل من أي جهاز أو خادم بدون عنوان عام. هذا أهم فرق تيليجرام عن
واتساب.

### ٤) (اختياري) Webhook بدل Polling

```env
TELEGRAM_WEBHOOK_URL=https://example.com/telegram/webhook
TELEGRAM_WEBHOOK_SECRET=كلمة-سرية
```
البوت يسجّل الرابط عند الإقلاع ويتحقق من السرية قبل قبول أي تحديث.

### ٥) ما يعمل على القناتين معًا

| الميزة | واتساب | تيليجرام |
|---|---|---|
| مؤشر "يكتب الآن…" | ✅ | ✅ |
| وسائط (صورة/صوت/فيديو/PDF) | ✅ | ✅ |
| الأوامر `/بوت` `/بشري` `/مسح` `/ايقاف مؤقت` `/مساعدة` | ✅ | ✅ |
| تحويل بشري + تنبيه | ✅ | ✅ |
| ردود يدوية من اللوحة (تتوزّع للقناة الصحيحة تلقائيًا) | ✅ | ✅ |
 — وسيردّ البوت 🎉

## 🔧 إضافة أداة جديدة (Function Calling)

الأدوات الحالية في `src/agent/tools.ts` ترجع **بيانات تجريبية**.
لربطها بأنظمتك الحقيقية، عدّل جسم الدالة فقط:

```ts
async capture_subscription_lead(args, ctx) {
  // 🔁 اربط هنا CRM/نظامك: POST للـ API، أو INSERT في قاعدة بيانات، أو Slack…
  const ref = await crm.createLead(args);
  return {
    ok: true,
    data: { ref },                                 // ما يراه النموذج
    userMessage: `✅ تم تسجيل طلبك — الرقم المرجعي: ${ref}`,  // يُرسل للعميل مباشرة
    sideEffect: { kind: 'notify_human', payload: { note: '💼 ليد جديد: ' + args.restaurant_name } },
  };
}
```

**لإضافة أداة جديدة** (٣ خطوات):
1. تعريفها في `TOOL_DECLARATIONS`
2. تنفيذها في `TOOL_HANDLERS`
3. ذكرها في كتلة الأدوات داخل `src/agent/systemPrompt.ts`

## ⚙️ أهم الإعدادات

| المتغير | الافتراضي | الشرح |
|---|---|---|
| `BOT_MODE` | `hybrid` | `business` خدمة عملاء / `assistant` مساعد شخصي / `hybrid` الاثنين |
| `BOT_NAME` | `مساعد` | اسم البوت كما يقدّم نفسه |
| `BUSINESS_NAME` | `الشركة` | اسم النشاط |
| `MAX_REPLY_PARTS` | `4` | أقصى عدد أجزاء في الرد الواحد لكتابة غنية وتفاعلية |
| `HISTORY_TURNS` | `36` | كم رسالة سابقة تُرسل للنموذج (مع ملخص دائم للمحادثات الطويلة) |
| `SESSION_TTL_MINUTES` | `45` | خمول بعدها تُعتبر المحادثة جديدة |
| `RATE_LIMIT_PER_MIN` | `15` | حد رسائل العميل في الدقيقة |
| `GEMINI_THINKING_BUDGET` | `0` | `0` = أسرع وأرخص، `-1` = النموذج يقرر |
| `TYPING_INDICATOR` | `true` | مؤشر "يكتب الآن…" |
| `HUMAN_AGENT_ID` | *(فارغ)* | رقم الموظف الذي يستقبل تنبيهات التحويل |

القائمة الكاملة مع الشرح في `.env.example`.

## 🌐 نقاط الـ API

| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET | `/webhook` | تحقّق Meta (`hub.challenge`) |

| POST | `/api/sessions/delete` | تصفير محادثة |
| POST | `/api/knowledge/reload` | إعادة تحميل قاعدة المعرفة |
| POST | `/internal/simulate` | محاكاة webhook (وضع التجربة فقط) |

## ⚠️ قيود يجب أن تعرفها من WhatsApp

| القيد | التفصيل |
|---|---|
| **نافذة ٢٤ ساعة** | بعد آخر رسالة من العميل لديك ٢٤ ساعة للرد بحرية. بعدها **يجب** استخدام قالب معتمد (Template) |
| **حد الرسالة** | ٤٠٩٦ حرفًا — المشروع يقسّم تلقائيًا عند `MAX_SEGMENT_CHARS` |
| **التسعير** | المحادثات تُحتسب حسب الفئة (marketing / utility / authentication / service). ردود الخدمة داخل نافذة ٢٤ ساعة غالبًا مجانية أو الأرخص |
| **الحظر** | لو أبلغ المستخدمون عن رسائلك كإزعاج، قد يُقيَّد رقمك |
| **الرقم** | الرقم المسجّل في Cloud API لا يمكن استخدامه في تطبيق واتساب العادي في نفس الوقت |

## 🩺 استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| Meta ترفض الـ Callback URL | تأكد أن الرابط **HTTPS**، وأن `WHATSAPP_VERIFY_TOKEN` مطابق تمامًا، وأن الخادم يعمل والنفق مفتوح |
| `401 invalid signature` في السجلات | `WHATSAPP_APP_SECRET` خاطئ — انسخه من App settings → Basic |
| البوت لا يرد | تحقق: `DEMO_MODE`؟ هل المحادثة في حالة `human`؟ هل تجاوز العميل `RATE_LIMIT_PER_MIN`؟ |
| `API key not valid` | مفتاح Gemini خاطئ أو غير مفعّل — أعد إنشاءه من AI Studio |
| الردود بطيئة | اضبط `GEMINI_THINKING_BUDGET=0` واستخدم موديل `flash` |
| الردود طويلة جدًا | قلّل `MAX_SEGMENT_CHARS` وشدد على الاختصار في `knowledge/tone-and-replies.md` |
| الوسائط لا تُفهم | تأكد من `MAX_MEDIA_BYTES` وأن التوكن يملك صلاحية الوسائط |
